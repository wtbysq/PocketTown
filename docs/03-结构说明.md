# 口袋小镇 · 结构与技术说明

> 版本 **1.2.0**（versionCode 44，minSdk 28 / targetSdk 34）· APK 约 830 MB（语音内置、大模型外置）· 文档更新于 2026-11-17
>
> 1.2.0 起改名「口袋小镇 / PocketTown」，包名 `com.koudai.town`；打包策略改为「语音进包、三档模型各一个模型包」。

---

## 1. 定位与技术栈

一台安卓手机上的**完全离线 AI 聊天应用**。会话即联系人，支持多人群聊；模型、语音、数据全部在本机，除 `127.0.0.1:8080` 外不发起任何网络请求。

| 层 | 选型 | 说明 |
|---|---|---|
| 界面 | 原生 JS 单文件（无框架、无构建、无 npm） | `app/assets/index.html`，约 3700 行 |
| 桥接 | `@JavascriptInterface` 注入 `window.Koudai` | 24 个方法 |
| 原生 | Java（无 Gradle，自建 aapt2 + javac + d8 流水线） | 5 个类，约 2600 行 |
| 推理 | llama.cpp b11669（`libllamaserver.so`，arm64） | 文本 CPU / 视觉 Adreno OpenCL |
| 语音 | sherpa-onnx + onnxruntime | SenseVoice int8 识别、VITS 16k 朗读 |
| 模型 | 1B：MiniCPM-V 4.7 Q4_K_M + mmproj；2B / 4B：Qwen3-VL Q4_K_M + mmproj | 三档各自导入：1.66 / 1.79 / 3.10 GB |
| 存储 | WebView localStorage（会话）+ 应用私有目录（模型） | 无数据库、无账号 |

## 4. 数据模型

一条 session 既可能是「联系人（单聊）」也可能是「群聊」，用 `kind` 区分：

| 字段 | 适用 | 说明 |
|---|---|---|
| `id` | 全部 | 时间戳 + 随机后缀，避免同毫秒碰撞 |
| `kind` | 全部 | `single` / `group` |
| `title` | 全部 | 联系人名 / 群名，**全局不重名**（@ 依赖名字唯一） |
| `avatar` | 全部 | 预设头像（dataURL）或相册导入（256 px JPEG dataURL） |
| `persona` / `memory` | single | 人设、长期记忆（≤400 字，超了截断），每次请求注入 system |
| `voice` / `read` | single | 音色 key、自动朗读开关（每人独立） |
| `notes[]` | single | 记忆卡 `{id, text, at}`，一条 ≤60 字、≤30 条 / 合计 900 字 |
| `members[]` | group | 联系人 id 列表，2–10 人 |
| `lastWho` | group | 上一位发言人；没 @ 时由它接话 |
| `msgs[]` | 全部 | `{role, text, img, ts, who?, cand?, stat?}`，`who` 仅群里有，`cand` 是候选记忆 |
| `at` | 全部 | 最近活动时间，用于列表排序 |

**全局用户资料 `S.me`**（一份，所有会话共用，不挂在 session 上）：

| 字段 | 说明 |
|---|---|
| `name` / `bio` | 称呼、签名（「我」页标题位就地编辑） |
| `city` / `job` / `family` / `like` / `avoid` | 城市 / 工作 / 家人 / 喜好 / 雷区，由 `FACT_FIELDS` 驱动渲染 |

**注入顺序**：人设 → 用户资料（`meBlock`，问答式）→ 长期记忆 → 记忆卡 → 规则与时间。用户资料**单独成块**，
不混进人设：混在一起时 1B 会把它当成自己的属性（`session.facts` 时代实测把用户名字认成自己）。
`load()` 里 `normalizeMe()` 负责补字段并从旧 `session.facts` 迁移（取第一个非空值，不覆盖已有全局值）。

**上限常量**：`MAX_MEMBERS = 10`、`MAX_CONTACTS = 300`、`MAX_GROUPS = 40`、`MAX_MEMORY_CHARS = 400`（保存时校验，不只靠界面禁用）。

**持久化**：`localStorage["pocketcpm.v1"] = { sessions, opts, me }`；迁移标记 `pocketcpm.mig`。

### 5.4 关键流程

**启动**：`load()`（补字段 + `normalizeMe` 迁移旧 `facts` + 一次性纠正自称）→ `renderHome` → 原生侧解模型/初始化语音 → `probe()` 探活 → 顶部绿点。

**发送（单聊）**：push 用户消息 → `detectFacts` 命中则挂候选胶囊 → 占位气泡 → `systemPrompt`（人设 → `meBlock` 用户资料 → 长期记忆 → 记忆卡 → 规则 → 时间 → 身份）→ 最近 9 条历史 → 流式或整段 → `fixSelfName` → 落库 → 可选朗读。

**流式 / 非流式**：`S.opts.stream` 默认开。流式走 SSE 逐行解析（`data:` 前缀，边收边渲染）；关掉后一次 `r.json()` 拿完，统计文案从「首字」换成「整段」，`chunks` 保持 0、token 只信 `timings.predicted_n`。回声重试固定走非流式，不受开关影响。

**提示词行为**：system 末尾注入手机本地日期与时刻（每次请求现取），并明确四条硬规则——不自我介绍、只有被问才报名字、不复述用户的话、不把对方的状态写成自己；附一条示例压住“我也累”这类镜像。用户消息尾部不再注入身份提醒（那是“每句都自我介绍”的直接原因）。

**图片内存保护**：长边上限 1280，另有总像素上限 1.2 MP；按可用内存分档（<2.3 GB 拒收，2.3–2.8 GB → 768，2.8–3.2 GB → 896，≥3.2 GB 按设置）；发送前二次校验；识图请求失败且引擎被回收时自动重启引擎并提示。门槛依据见 docs/06：视觉编码固定吃 1.06~1.32 GB，与图片尺寸几乎无关。

**发送（群聊）**：`mentionedAll` 解析 @（可多个）→ 逐个 `replyOne`；每位用自己的人设/记忆/音色；**历史里别人的话放用户侧并加名字**，只有自己的话是 `assistant`，避免身份串味；上下文收窄到 7 条。

**删除**：长按行 → 确认框（联系人会提示"还在 N 个群里"）→ 同步清理群成员与 `lastWho`。

**导入**：设置选 zip → 原生流式解压 → 校验 manifest 与路径（禁 `..`）→ 增量覆盖（大小一致则跳过）。

**读文档（.docx）**：输入栏「＋」→ 文档 → `ACTION_OPEN_DOCUMENT` → 原生后台线程用 `DocxReader`（ZIP + SAX，零依赖）解析 `word/document.xml` → `window.onDocReady` 回调 → JS 用 `docChunk` 分片拉正文（原生随即 `docClear` 释放）→ `splitDoc` 按段落切 900 字块（超长段硬切）→ 逐块非流式请求"抄 120 字要点" → 把要点合并再请求一次出最终答复。

- 块数上限 40（超过劝退，1B 上一块要几秒到十几秒）；请求固定 `stream:false`，进度用一行提示代替逐字
- 只读正文：页眉页脚、脚注、批注、修订（`w:delText`）不读，表格压成 `a | b`，图片/公式留空
- 老版 `.doc`、加密文档、PDF 不是 ZIP，读前用魔数 `PK\x03\x04` 拦下并提示另存为 .docx

**切换模型**：模型页结构是「当前模型卡片 + 模型档案列表」两块。卡片由 `paintModelPage()` 按
`loadedModelId()` 渲染——以 `/props` 的 `model_path` 判断引擎里真正跑的是哪档，拿不到才退回原生偏好；
列表每行是 `名称 · 体积 · 状态`，点一行 → `switchModel()`（**唯一入口**，别在别处直接调 `NATIVE.setModel`）
→ `askConfirm` 说明耗时与内存 → `NATIVE.setModel(id)`（原生写偏好 → `restartEngineInternal` 停旧进程 →
`boot()` 载新权重）→ JS 每秒 `probe()` 直到 `/health` 通，再比对 `nativeInfo().model` 确认跑的真是这一档
→ 成功收起遮罩；失败则 `setModel(原档)` 退回（原生已自己退回时跳过）。删除按钮在同一列表里，
正在用的那档显示「使用中」并禁用。
原生侧另有一道保险：`boot()` 里非 1B 档启动失败且 1B 存在时，把偏好改回 1B 再 `boot()` 一次（`fellBack1b` 防递归），避免下次开机直接进不去。
`boot()` 选档时只在**非 1B** 档缺文件的情况下才去挑别的档；1B 缺文件说明内置副本还没解出来，得留在 1B 走 `extractParts` 解包——否则点「切回 1B」会被悄悄降级成盘上现成的 4B。
引擎就绪后 `boot()` 还会调 `prefetch1b()`：当前跑的不是 1B、1B 又不在盘上（删过），就在后台把内置副本解出来（静默、要求 ≥2 GB 空闲），所以切回 1B 只是换权重，不会卡在解包上。

**存档 / 恢复**：
- 导出：`archivePayload()` → 180 KB 分片 → `archiveFinish` 一次写盘 → `Download/口袋小镇/koudai-存档-时间戳.json`
- 恢复：SAF 选文件 → 原生读入（≤40 MB）→ 页面分片取回 → 校验 `app`/`sessions` → **先自动导出当前数据** → 覆盖 → 补字段 → 刷新
- 分片原因：避免数 MB 字符串一次性跨 WebView 桥导致卡顿或失败

### 6.2 引擎启动参数

```
-m 1B.gguf -mm mmproj.gguf --host 127.0.0.1 --port 8080
-c 8192 --cache-type-k q8_0 --cache-type-v q8_0
-t 4 -ngl 0 --mmproj-offload
```

- **8192 tokens 上下文**，KV cache q8 量化（同样内存装两倍上下文）
- 实测引擎 RSS ≈ 928 MB，系统剩余 ≈ 2.6 GB
- **失败自动回退**：8192 起不来 → 4096 + 关闭量化 → 再不行退回纯 CPU（关 OpenCL），保证一定可用

### 6.3 语音子系统

| 能力 | 模型 | 位置 |
|---|---|---|
| 识别 | SenseVoice int8 + tokens | `files/speech/asr/`（229 MB） |
| 朗读 | VITS 16k，6 音色 | `files/speech/{tts,tts_m,tts_bronya,tts_theresa,tts_zzl,tts_doom}/` |

音色表：`female`（女声·温柔）、`bronya`（女声·清冷）、`theresa`（女声·活泼）、`male`（男声·标准）、`zzl`（男声·沉稳）、`doom`（男声·低沉）。**六个音色都随 APK 发布**（`assets/speech/tts*`），女声在启动时解出做兜底，其它音色在 `setVoice()` 里按需解出（每个约 130 MB）；缺失时自动退回 `female`。`deviceInfo().bundledVoices` 告诉页面哪些音色是随包发的，页面据此把按钮点亮。

## 8. 打包与签名

**流水线**（`app/build-apk.sh`，六步）：

```
[1/6] aapt2 编译资源        [2/6] 生成 R.java
[3/6] javac 编译 Java       [4/6] d8 转 dex
[5/6] pack.py 组装 APK      [6/6] zipalign + apksigner 签名
```

```bash
cd /d/kcpm      # ASCII 别名，等价于 D:\口袋CPM\project
TARGET_SDK=34 OUT_NAME=PocketTown-1.2.0.apk bash app/build-apk.sh
```

- 默认**只打语音**（ASR + 6 个音色，约 830 MB），三档模型由 `make-model-zip.py` 出的 zip 导入
- `BUNDLE_MODELS=1` 才把 1B 主模型 + mmproj 分片塞进 `assets/models/`（整合包约 1.9 GB）；此时 `boot()` 会把 1B 从 assets 解出、`prefetch1b()` 会在跑别的档时后台预解，页面靠 `deviceInfo().bundled1b` 区分两种包
- `pack.py` 的原生库来自 **`app-ocl/`**（含 OpenCL）+ `speech/libs/`（onnxruntime、sherpa-jni）
- **签名密钥固定在 `project/app/koudai.keystore`**（alias `koudai` / `koudai123`）。**绝不能放进 `build/`**——`build/` 每次构建被清空，会导致签名变化、无法覆盖安装（已踩过此坑）

## 9. 权限与安全

**权限**（`AndroidManifest.xml`）：

| 权限 | 用途 |
|---|---|
| `INTERNET` | 仅访问 `127.0.0.1:8080` |
| `RECORD_AUDIO` | 语音输入 |
| `FOREGROUND_SERVICE` / `..._DATA_SYNC` | 引擎保活 |
| `POST_NOTIFICATIONS` | 通知栏「结束引擎」 |
| `WRITE_EXTERNAL_STORAGE`（maxSdk 28） | 旧系统导出存档 |

**已实施的安全措施**：

- `shouldOverrideUrlLoading` 白名单：只放行 `file:///android_asset/`、`127.0.0.1:8080`、`about/data/blob`，其余拦截并记录日志（防止远端页面拿到原生桥）
- Markdown 渲染**先转义再处理格式**，不生成 `<a>`/`<img>`，模型输出无法注入 HTML/JS
- 导入 zip 校验 manifest 与 `..` 路径穿越
- 存档恢复前校验 `app` 标识，并自动备份当前数据

**已知取舍**：引擎监听 127.0.0.1 且**未设 api-key**（同机其它应用理论上可访问）；加 `--api-key` 可能影响 `/health` 探活，列入下版本评估。

## 12. 已知限制

1. **引擎无鉴权**：见第 9 节，建议下版本加 `--api-key` 并适配探活。
2. **上下文 8192 tokens**（约 3000 汉字）+ 仅带最近 9 条（群里 7 条）：长对话靠"人设 + 长期记忆 + 记忆卡"维持连续性，不是全量历史。
3. **localStorage 约 5–10 MB**：图片多时会自动丢弃最老的 12 张，属预期行为。
4. **切音色阻塞约 1 秒**：同步加载模型，体验问题非缺陷。
5. **1B 能力上限**：复杂推理、长文分析偏弱；群聊多人时偶有口吻漂移（已有三层名字锁定兜底）。
6. **无云备份**：卸载即丢内部数据；请用「导出存档」+ 模型 zip 备份。
7. **35B 代码保留但禁用**：本机 11 GB 内存跑不动，需 16 GB 以上机型，当前版本不开放入口。
8. **仅 arm64**：不支持 32 位设备与模拟器 x86。
9. **1B 的记忆边界**：「你还记得我叫什么、在准备什么」这类第二人称 + 自指混合问句仍不稳；资料里没有的信息（住哪、多大）可能被编造。
10. **候选记忆靠正则**：`detectFacts` 只认明确句式，绕弯说法抓不到；群聊不捕获（分不清对谁说）。
11. **文档只读 .docx 的正文**：老版 `.doc`、加密文档、PDF、扫描件（整页是图）都读不了；页眉页脚/脚注/批注/修订不读；表格压成 `a | b`，合并单元格关系丢失。
12. **文档只能读不能改**：不回写 .docx（写回要自己拼 XML 并保样式，属另一个量级的工作）。
13. **长文档靠分块**：单块 900 字、最多 40 块，跨块的连贯性由"分段要点合再答一次"近似，1B 做得不稳，细节可能丢。
14. **Qwen3-VL 档只能文字**：视觉塔在现有 `libmtmd.so` 上必崩（`clip_encode → ggml_gallocr_alloc_graph`，真机 tombstone 确认），所以图片入口对 2B/4B 直接拦掉；要看图只有 1B。
